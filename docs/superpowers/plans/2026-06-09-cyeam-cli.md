# Cyeam CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `cyeam` Go CLI described in `docs/superpowers/specs/2026-06-09-cyeam-cli-design.md`.

**Architecture:** The CLI is a Go HTTP client for public cyeam.com routes. Cobra owns command parsing; small internal packages own HTTP requests, output handling, version metadata, and update logic.

**Tech Stack:** Go 1.23+, Cobra, standard library HTTP/multipart/SSE-style streaming, `httptest` for tests.

---

## File Structure

- Create `go.mod` and `go.sum`: module and dependencies.
- Create `cmd/cyeam/main.go`: executable entrypoint.
- Create `internal/cli/root.go`: Cobra command tree and dependency injection.
- Create `internal/client/client.go`: HTTP client, URL construction, JSON requests, streaming, multipart upload, binary download.
- Create `internal/output/output.go`: JSON stdout and file output helpers.
- Create `internal/version/version.go`: version metadata.
- Create `internal/update/update.go`: GitHub Release lookup and asset selection.
- Create matching `*_test.go` files for each internal package.

## Self-Review

This plan covers the command tree, public API mapping, fixed production base URL, no config command, xingshu-only Mo behavior, roadbook URL output, GitHub Release update source, and unsupported feature boundaries. It intentionally does not include changes to `cyeam_web`; the CLI date commands target the planned `/api/date/*` routes from the design document.
