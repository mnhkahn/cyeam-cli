# CNote Get Command Design

## Goal

Add a command for reading a cloud note from OneDrive without printing raw
HTML. The command should be useful in terminal workflows and preserve enough
structure for copying into Markdown documents.

## Command

```bash
cyeam cnote get <title> [--format markdown|text]
```

- `<title>` maps to `Notes/<title>.html`, matching `cnote new` and
  `cnote append`.
- `--format` defaults to `markdown`.
- `markdown` outputs terminal-readable Markdown-like content.
- `text` outputs plain terminal text with list and line structure preserved.
- Raw HTML output is intentionally not supported.

## Data Flow

1. `cnote get` builds `<title>.html`.
2. The command reads the note with the existing OneDrive client:
   `ReadFile(ctx, "Notes", filename)`.
3. The returned HTML is converted locally.
4. The converted content is written to stdout with a trailing newline.

## HTML Conversion

The converter should be conservative and dependency-free:

- Decode HTML entities.
- Convert headings to Markdown headings in `markdown` and plain lines in
  `text`.
- Convert paragraphs, divs, and line breaks to readable newlines.
- Convert unordered and ordered list items to `- item` and `1. item` style
  lines.
- Preserve link text and include destinations in Markdown as
  `[text](url)`. In text output, include `text (url)` when the URL differs
  from the visible text.
- Convert strong/emphasis tags to Markdown markers only in Markdown output.
- Strip unsupported tags while keeping their text.
- Collapse excessive blank lines.

This is not a full browser-grade HTML renderer. It is a pragmatic converter
for CNote HTML generated by the existing note workflow.

## Error Handling

- Missing title uses Cobra's exact argument validation.
- Invalid `--format` returns a clear error before reading OneDrive.
- OneDrive read errors are wrapped as `read note: <error>`.

## Testing

Add focused CLI tests for:

- `cnote get` defaults to Markdown.
- `--format text` returns plain text.
- Invalid format is rejected.
- The converter handles headings, paragraphs, line breaks, lists, links,
  emphasis, and entity decoding.

Run the root CLI tests and the full Go test suite after implementation.
