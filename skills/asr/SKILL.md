# 语音转文字（ASR）

通过 `cyeam asr` 调用 cyeam.com 语音识别接口（服务端代理到 ASR 模型），把本地音频转成文字。无需登录、无需配置。

## 用法

```bash
cyeam asr <audio-file>
cyeam --pretty asr <audio-file>
```

默认输出 JSON 信封，`data` 含 `file` 和 `text`；`--pretty` 只输出识别文本。

## 约束

- 支持常见音频格式：m4a、mp3、wav、webm、ogg、aac、flac、amr、3gp、opus，按扩展名设置上传 Content-Type。
- 单个文件不能超过 15MB（服务端限制），超出会直接报错。
- 识别需要联网；接口不可用时命令返回错误，不要自行拼装 HTTP 请求代替。

## 识别质量说明

- 对儿童语音、有背景人声或噪声的录音，识别文本可能混入杂音内容或错字。判读作业时应以识别文本为参考证据，结合原题要求判断；明显是背景人声的片段（如家长说话）不要算成孩子的跟读错误。
- 只有一段录音、没有原文可对照时（如听力题），不能据此判定内容对错，只能确认是否完成朗读。

## 朗读原文对齐

拿到原文和 ASR 转写比较时，先保留原始转写，再建立用于对齐的规范化副本，不能直接把逐词 diff 或 WER 当作孩子的朗读错误。

- 先忽略大小写、断句、空白、标点和直/弯撇号差异。英语录音中混入的表情不算朗读词；中文或背景人声先单独标注，不能把整段听不清的内容一律删除后声称读对。
- 上下文意义相同的缩写与展开形式按等价处理，例如 `it's ↔ it is`、`we're ↔ we are`、`don't ↔ do not`；ASR 的 `its/it's`、`we're/we are` 等书写差异不列为错词。`'s` 可能是 `is`、`has` 或所有格，`'d` 可能是 `had`、`would`，必须结合上下文，不能统一展开或忽略所有包含缩写的差异。`our robot is ready` 与 `our robot it's ready` 涉及额外主语，不是单纯缩写差异，仍保留为待核对。
- 朗读评价中，上下文能确定的同音词转写（如 `we meet` 被写成 `we meat`）不作为发音错误；拼写、听写或语法任务不套用这条例外。近音词、不同实词、单复数、时态及第三人称词尾不能按同音等价直接删除。
- `go go`、`is is` 这类相邻无实质意义的重复，可在内容对齐时折叠，单独记录为重复/流畅度现象，不算内容替换或缺词；保留原始重复，不据此断言是 ASR 生成还是孩子重复。
- 按句段检查对齐，避免机械逐词匹配把一次漏识别扩散成后面一串“错词”。先报告被排除的等价差异，再列剩余待核对片段；若给统计，写明规范化规则、比较单位和分母，并区分原始文本差异、规范化后的差异与已听音确认的朗读错误。不能把 `1-WER` 称为孩子准确率。内容已经确定漏读、错读前，应核听对应录音；仅有 ASR 证据时标为待核对。

- 高频差异反馈默认只统计替换，按“原文词 → ASR 词”分组计数，优先展示同方向重复 ≥2 次的项；缺失和多出不进入重点词榜或替换评分。保留原始差异以便核听，不能断言缺失就是没读或替换一定读错。
- 默认从替换榜及阅读参考分中排除低信息功能词，例如 `is`、`to` 等 be 动词、冠词、常用介词和连词；常用默认列表为 `am/is/are/was/were/be/been/being/a/an/the/to/of/in/on/at/for/from/with/by/and/or/but`。正文中的主语、人称、否定等实质意义变化仍保留在核听材料中，不因过滤而声称语法正确。优先反馈实词及词尾，例如 `robotics → robot`、`robots → robot`；计次数同时展示目标词和原句，不能只给总差异率。

## 作业场景

提取 Trello 作业时使用 `cyeam trello homework --board <board-id> --asr`，可直接获得各类作业音频附件的 `transcript` 字段，失败原因在 `transcript_error`，无需逐个调用本命令。`--asr=false` 关闭转写；未传时仍仅英语卡片自动转写。已有报告中的文本直接读取即可；报告里没有识别文本或识别失败时，用本命令对附件的 `saved_to` 路径手动转写。详细流程见 homework skill。
