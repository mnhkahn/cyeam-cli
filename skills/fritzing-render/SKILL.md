# Fritzing 接线图

把元件和接线保存在可编辑源文件中，按用户需要导出展示图。在已有项目中先找 `.fzz`、`.fz`、JSON 草图及 README；修改接线时从现有源文件继续。

## 核对接线

- 看用户最近确认的接法、实物照片、固件引脚配置和接线文档。固件能说明 GPIO 的功能，实物照片和用户确认用于定位板上的端子。示例代码、旧接线和商品图只能支持它们各自描述的版本或接法。
- 核对每个端点的板型、方向、丝印、信号流向和电压。对带跳帽的电源模块，明确所画的是哪组输出以及哪一档。未知的端子位置或走线在图上标注待确认。电源线、GND 和信号线沿用项目已有的配色。
- 先用零件库查准确型号和引脚。需要表现实物时，可以依据照片与引脚图绘制自定义元件。只掌握端子功能时，用带标签的示意部件，避免把功能端子画成已确认的实体焊盘。

## 编辑与导出

- 在 Fritzing 桌面版编辑 `.fzz`。已有 `.fzz` 可直接用 `fritzing-render` 预览和导出。网页 **Editor** 编辑 JSON 草图，**Sketches** 接收 `.fzz`、`.fz` 和 JSON 用于渲染。
- 优先使用可用的本地 CLI。Docker 可用时使用官方容器镜像。也可把草图打开到 `fritzing-render` 网页，查看相应视图并下载。命令、格式例子和自定义元件打包说明见 [渲染与草图格式](references/fritzing.md)。
- 交付 `.fzz` 时把自制元件打包在源文件中。网页编辑器的项目则保存 JSON，以及它依赖的自定义元件文件。要更新 README 时，在目标仓库保存源文件和 SVG，使用相对路径嵌入图及链接源文件。

## 验证交付

从交付的源文件重新渲染，检查错误、缺失元件、标签裁切和交叉处的连通含义。改动了供电或 GPIO 时，按源文件的连接端点核对电源、地和信号。同步更新受影响的视图和图例，并核对 README 链接。报告实际验证过的渲染或编辑环境。
